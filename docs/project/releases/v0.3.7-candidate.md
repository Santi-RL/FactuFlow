# FactuFlow v0.3.7 — mantenimiento y confiabilidad

Estado: **PUBLICADO; REVISIÓN MANUAL POSTERIOR PENDIENTE**.
Última actualización: 04/10/2026.

## Alcance del corte

La release reúne el mantenimiento aceptado desde `v0.3.6`: reintentos seguros,
condición IVA obligatoria del receptor, saneamiento documental y de código,
hora argentina, asociación administrativa posterior a CAE y dependencias.
Los contratos y las evidencias anteriores permanecen en sus dossiers y en el
changelog; este documento define el corte y su recuperación.

La preparación final actualiza pytest a 9.0.3, pytest-asyncio a 1.3.0 y Black
a 26.3.1. La auditoría Python incluye runtime y desarrollo. El ciclo de eventos
de sesión se configura mediante el plugin, con aislamiento de datos por prueba.
El formato de Black conserva la estructura ejecutable de los archivos; la
versión del producto se alinea en paquetes, API e interfaz.

El conjunto se trata como Nivel 2 por los cambios fiscales acumulados y el
despliegue. No implementa A01 ni A03 ni las iniciativas posteriores del roadmap.
Esos hallazgos previos conservan su prioridad; no se declaran resueltos por
publicar esta release. El desarrollo siguiente espera la revisión manual del
usuario sobre la nueva versión.

## Contratos fiscales preservados

El checklist fiscal se aplica al rango completo. La condición IVA compatible
se valida antes de WSFE, sin convertir datos desconocidos en consumidor final.
La fecha fiscal permanece explícita y conserva su confirmación irreversible.
Los replays, reservas, guardas, aislamiento por emisor y estados inciertos
mantienen los contratos de idempotencia y reconciliación.

La asociación de cliente posterior a CAE usa el guardado compartido, preserva
el snapshot receptor y no selecciona arbitrariamente una ficha ambigua. Las
pruebas de emisión, lotes, reintentos, error de persistencia, concurrencia y
reconciliación usan dobles sintéticos; ninguna validación del corte solicita un
CAE real. La base conserva sus timestamps UTC sin zona explícita; la API
comunica la zona y la web presenta hora argentina. Los antecedentes cuya zona
no se acredita mantienen ese límite. Las fechas fiscales no sufren conversión
horaria.

## Compatibilidad y actualización

Tailwind CSS 4.3.3 requiere Firefox 128+, Chrome/Edge 111+ o Safari 16.4+.
La ampliación del requisito de Firefox fue aceptada por el usuario. El build de
la imagen frontend y la matriz E2E comprueban estilos y flujos existentes.

El preflight compara el SHA realmente ejecutado en la instalación con el SHA
congelado. El origen observado ya incorpora los parches de reintentos y condición
IVA posteriores a `v0.3.6`; su identidad y el diff operativo verificado quedan
en la evidencia privada del plano de control. Desde ese origen, el rango
revisado no introduce revisiones Alembic, cambios semánticos de persistencia,
requisitos Python de runtime ni variables de configuración nuevas.

Ese resultado no se extrapola al rango desde el tag `v0.3.6`: el corte completo
incluye PyJWT 2.15.1, WeasyPrint 70.0 y pypdf 6.19.0, y retira passlib. Estos
cambios ya forman parte del origen productivo observado. La construcción
frontend y las herramientas Python sí se actualizan respecto de ese origen.
Se reconstruyen las imágenes desde el SHA aprobado;
no se despliega una referencia móvil. La evidencia concreta de la instalación
permanece en el plano de control privado.

## Recuperación y puertas de salida

Antes de publicar y desplegar deben quedar cerrados:

- suite backend completa con PostgreSQL desechable, cobertura y advertencias
  estrictas; lint, formato, tipos, frontend, scripts, smoke y E2E aplicables;
- auditorías completas de Python y npm, revisión del rango y siete controles
  obligatorios de CI sobre el candidato y su integración;
- respaldo reciente de base, configuración, archivos e imágenes vigentes,
  checksums y restauración PostgreSQL aislada con esquema, constraints y
  agregados equivalentes;
- ensayo aislado del runtime objetivo y disponibilidad de las imágenes del
  rollback, sin certificados operativos ni acceso a ARCA;
- ventana acotada de mantenimiento, ausencia de trabajo fiscal nuevo en curso,
  smoke del SHA exacto y conservación del historial y estados inciertos.

El rollback previsto vuelve a las imágenes anteriores con la misma base, sin
restaurar datos ni ejecutar downgrade automático. Si existe trabajo fiscal
nuevo o incierto, primero se determina su estado seguro. Una restauración de
datos productivos requiere una decisión separada. Los estados legacy no se
reconcilian ni se reintentan como parte del mantenimiento.

## Publicación y evidencia técnica

La [release v0.3.7](https://github.com/Santi-RL/FactuFlow/releases/tag/v0.3.7)
se publicó el 04/10/2026. El tag anotado e inmutable resuelve a
`83bbc5450bd4fec5acf83ac510a9637984a50097`, integración del
[PR #73](https://github.com/Santi-RL/FactuFlow/pull/73). Su árbol coincide con
el candidato revisado y probado; la rama temporal quedó retirada.

La [CI de propuesta](https://github.com/Santi-RL/FactuFlow/actions/runs/37225853270)
y la [CI integrada](https://github.com/Santi-RL/FactuFlow/actions/runs/37227014550)
aprobaron los siete controles obligatorios, sin anotaciones ni advertencias
inesperadas de ejecución. La integración registra 1542 pruebas backend,
cobertura 73,59 %, 273 frontend y 38 E2E. El smoke verifica API, PostgreSQL y
Vue; las auditorías completas de Python y npm no detectan vulnerabilidades.
El grafo nativo de Dependabot terminó correctamente con un notice informativo
del proveedor sobre su runner; el workflow del proyecto conserva Ubuntu 24.04.

La suite local Linux del snapshot final también aprobó sus 1542 pruebas,
incluidas PostgreSQL y PDF, con cobertura 73,58 %. Se ejecutó con worker
habilitado, fixtures sintéticos y conexiones externas bloqueadas. Una
interrupción nativa de Windows no se tomó como evidencia de aprobación ni se
omitieron sus casos PDF. Ruff, Black, tipos, lint, build, 30 pruebas de scripts,
cinco semillas Clawpatch y alineación documental aprobaron. La revisión
independiente quedó sin hallazgos pendientes. Dependabot confirmó las alertas
de pytest, Black y braces como corregidas, sin descartarlas manualmente.

El plano de control verificó respaldo reciente, checksums, restauración
PostgreSQL aislada y copia off-VPS cifrada con apertura independiente. El ensayo
de imágenes del SHA congelado aprobó upgrade y rollback sobre la misma base
sintética, preservando esquema, filas e historia incierta; Nginx, assets y API
funcionaron juntos, con cero conexiones externas o llamadas ARCA. El runtime
conserva sus 72 paquetes y las herramientas de desarrollo quedan fuera de la
imagen productiva. Las imágenes se construyeron sin advertencias.

El usuario autorizó el despliegue seguro y su QA manual posterior. Esta
publicación no declara completada su aceptación funcional ni inicia las
implementaciones siguientes.

El estado desplegado autoritativo se registra exclusivamente en
`VPS Hostinger` / `vps-admin`; la publicación de un tag no acredita producción.
